## F. Riset VPS & rencana rotasi akun (belum dieksekusi)

### 1. Kebutuhan resource (dari pengukuran lokal, 5 akun jalan)
- Chrome ±7,3 GB total untuk 5 akun (±1,4–1,5 GB/akun), Node ±150 MB/akun, OS Windows ±2 GB.
- Perkiraan 1 akun di Linux: Chrome 1,2–1,5 GB + Node 0,15 GB + OS 0,4–0,7 GB + Xvfb ±0,05 GB
  ≈ 2–2,5 GB → **2 vCPU / 4 GB / 60 GB NVMe + swap 2 GB layak untuk 1 akun 24/7**.
- Windows VPS 4 GB tidak layak (OS saja 2–3 GB). 2+ akun bersamaan → 8 GB.
- vCPU 2 cukup (posting I/O-bound, jeda 15–30 dtk). Disk 60 GB aman; profil tumbuh 100–400 MB/akun.
- Chrome dijalankan `headless: false` → di Linux wajib **Xvfb**; sediakan **VNC** untuk login/2FA
  manual. Kode sudah cross-platform (dashboard spawn `process.execPath`; kill non-Windows SIGTERM).
- IPv4 sebaiknya **dedicated**; "shared IPv4" berisiko checkpoint. Pilih IP Indonesia/Singapore,
  statis, jangan ganti-ganti. Banyak akun di 1 IP datacenter menaikkan risiko keterkaitan akun.

### 2. Rencana mode rotasi (dashboard-only, worker tidak diubah, ±200 baris)
- State `rotation.json`: enabled, urutan LRU, cooldown per akun, akun perlu-manual.
- Hanya **1 worker aktif** pada satu waktu (pas untuk RAM 4 GB).
- Saat worker keluar:
  - LIMIT → cooldown (default 24 jam, configurable) → start akun berikutnya.
  - COMPLETED → akun ke belakang antrian → berikutnya (progress dihapus worker → siklus baru B1).
  - Safety-net stop / gagal login / crash 3x → akun di-skip (cooldown singkat/perlu manual) → lanjut.
  - Stop manual / Stop All → rotasi PAUSE; `/rotate on` untuk melanjutkan.
- Semua akun cooldown → timer ke akun paling cepat pulih + notifikasi "semua limit, lanjut HH:MM".
- Telegram: `/rotate on|off|status`; notifikasi perpindahan akun; sisa cooldown tampil di dashboard.
- Persisten + auto-resume saat dashboard hidup lagi (dipasangkan systemd di VPS).
- Uji lokal: fb03 (sudah LIMIT) + fb02 → verifikasi pindah akun, cooldown, pause, resume setelah
  dashboard restart. Lalu `npx tsc --noEmit`.
