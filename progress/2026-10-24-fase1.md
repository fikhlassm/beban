## B. SELESAI (working tree, BELUM di-commit)

### Worker (src/facebook-multi-account-worker.ts)
- Bucket harian di `posting-stats.json`: `daily: {"YYYY-MM-DD": {total,direct,pending,error,limited,unknown}}`
  - increment di `recordPostingResult`, dipertahankan saat reset lifetime (`resetPostingStats`), prune 30 hari
- Rotasi log: `log.txt` → `log-<tanggal>.txt` saat ganti hari (`rotateLog`), hapus rotasi >7 hari
- `stop.request` diperiksa saat menunggu login manual → STOP admin dihormati, worker keluar rapi (bukan kill-30-detik)
- Hardening BOM: `parseJsonSafe` untuk progress/config/posting-stats (Notepad menulis BOM → JSON.parse gagal senyap)

### Dashboard (src/telegram-dashboard.ts)
- `runtime.json` per akun: `lastStartedAt` + `daily` (durasi run, simpan 14 hari)
  - flush saat exit/shutdown; sisa sesi yang tidak ter-flush dikreditkan saat start berikutnya (`markWorkerStarted`)
  - durasi hari ini menyertakan prorata sesi berjalan sejak 00:00 (`runtimeTodayMs`)
- Tampilan list + `/view`: `⏱ durasi sesi • 📤 X post (n hari ini)` + breakdown
- Notifikasi stop diperkaya: `⏱ berjalan X • 📤 N posting sesi ini` (diff total stats vs snapshot saat START)
- Ringkasan harian: tombol `📊 Ringkasan` di dashboard + perintah `/ringkasan` (per akun + grand total + jumlah akun berjalan)
- Graceful stop via `stop.request` (worker keluar sendiri ≤1 detik), `taskkill /F` hanya fallback setelah 30 detik; `stopAll` paralel
- Auto-restart backoff 1m/2m/4m/8m/15m maks 5x (`RESTART_MAX_FAILURES`); counter reset bila sesi sehat >10 menit
  - TIDAK di-restart: LIMIT / COMPLETED / SETUP ERROR / manual stop / shutdown
- Watchdog hang: RUNNING + log diam 15 menit → alert admin → stop + restart terawasi (jalur `supervisedRestart`)
- Stagger Start All: jeda 30 detik antar akun; loop berhenti saat shutdown
- Guard race: `starting` set (double-start), `exitHandled` (error+exit double-fire), `hangAlerted` (alert berulang)
- State baru `SETUP ERROR` (grup/konten kosong → tidak di-restart, ikon ⚙️)
- `bot.launch().catch` → gagal launch (409) exit bersih, bukan proses zombie

### Status peluncuran terakhir
- Dashboard uji peluncuran ke-2: `TEST_MODE=1 HANG_TOLERANCE_MS=60000 WATCHDOG_INTERVAL_MS=30000 RESTART_MAX_FAILURES=1`
  output → `dash-test-out.txt` / `dash-test-err.txt`, hasil → `test-results.txt`
- **Masalah ditemukan**: output tetap 0 byte, tidak ada test-results, tidak polling getUpdates →
  kemungkinan 409 saat launch (dashboard lama melepas getUpdates ~50 detik pasca-kill).
  Instance ini SUDAH dimatikan di akhir sesi (PID 29864 taskkill /T /F) →
  **sekarang tidak ada proses dashboard/worker apa pun yang berjalan.**
- Hipotesis penyebab senyap: launch kena 409/transient → perlu luncur ulang bersih; pastikan
  getUpdates bebas konflik dulu (node fetch getUpdates?timeout=0 harus `{"ok":true}` tanpa 409)

### Tes yang diharapkan otomatis (harness TEST_MODE)
A. graceful stop: start fbtest → tunggu log "Ditemukan N grup" → STOP → harus "dihentikan rapi",
   progress tersimpan, `runtime.json` lastStartedAt null + daily[today] > 0
B. crash auto-restart: start ulang → tunggu "percobaan 1/x" → taskkill child → notif "tak terduga"
   → auto-restart ≤2 mnt (backoff 1m) → stop rapi
C. watchdog: start fbtest2 (tanpa sesi, hang di login-wait, toleransi 1 menit, interval 30 detik,
   maks restart 1) → alert hang → stop → restart → hang lagi → "tetap bermasalah" (give-up)

## D. LANGKAH BESOK (urutan)
1. Hapus `dash-test-out.txt`, `dash-test-err.txt`, `test-results.txt` (file lama, jika ada)
2. Cek bebas konflik getUpdates (harus `{"ok":true}` tanpa 409); kalau 409 → cari & matikan instance lain dulu
3. Luncurkan dashboard TEST_MODE (perintah di F bawah); pantau `dash-test-out.txt` + `test-results.txt`
   sampai selesai (± 12–18 menit). Admin menerima notifikasi Telegram asli selama tes
4. FAIL manapun → perbaiki → ulangi tes yang gagal
5. Verifikasi data: `accounts/fbtest/runtime.json` (daily[today] > 0, lastStartedAt null),
   `accounts/fbtest/posting-stats.json` bucket daily (kalau ada posting), notifikasi masuk di HP (konfirmasi user)
6. Cleanup: `Remove-Item -Recurse -Force accounts\fbtest, accounts\fbtest2` + file tes
7. Jalankan dashboard bersih (`npm run dashboard` di terminal user, tanpa TEST_MODE)
8. User tekan **▶ Start All** di Telegram → semua worker hidup dengan kode baru
9. Opsional jika diminta: commit `src/` — JANGAN ikutkan `akunbot`/`akunril` (sudah berubah duluan
   oleh user) dan jangan commit folder/file uji

## E. Risiko / temuan penting
- Cookies fb01 dipakai di browser-profile BARU (fbtest) → kadang FB minta checkpoint; kalau fbtest
  gagal login, tes B jatuh ke N/A-limit/setup — tercatat di results
- Maks 1–2 postingan asli "Uji cek — abaikan pesan ini" bisa terjadi (user sudah izinkan);
  stop tepat di batas "Ditemukan N grup" membuatnya 0 postingan
- Sesi menyeberang tengah malam: delta runtime dikreditkan penuh ke hari exit (penyederhanaan, disepakati)
- Diagnosa 409: getUpdates instance lama menahan sampai ~50 detik pasca-kill → tunggu ≥60 detik
  sebelum meluncurkan dashboard baru
- `akunbot` / `akunril`: sudah berubah oleh user sendiri sebelum sesi ini — jangan disentuh/di-commit
